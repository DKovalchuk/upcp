## Issue 1: MCP Endpoints Bypass Auth

**Severity:** High
**File:** `backend/app/identity/middleware.py:52`

### Problem

```python
if path.startswith("/mcp"):
    return await call_next(request)
```

The MCP server at `/mcp/` is explicitly skipped by the auth middleware. Anyone can call MCP tools including task CRUD, claims, evidence — no authentication required.

### Fix

Remove the MCP bypass. MCP endpoints should require either:
- JWT Bearer token (same as API), OR
- Agent token via `X-Agent-Token` header

The MCP router already has access to the request — it just needs the auth middleware to verify the token first.

If MCP needs a different auth mechanism (e.g., API key for external tools), add it as a separate check, not a bypass.

### Implementation

```python
# In middleware.py — REMOVE the MCP bypass:
# if path.startswith("/mcp"):
#     return await call_next(request)

# MCP endpoints are under /mcp which is under /api/v1 prefix check
# Wait — actually MCP is registered at prefix="/mcp", not under /api/v1
# So the middleware's `if not path.startswith("/api/v1/")` check already skips it

# Fix: extend the middleware to also protect /mcp/ paths
if not path.startswith("/api/v1/") and not path.startswith("/mcp"):
    return await call_next(request)
```

### Acceptance Criteria

- [ ] MCP endpoints return 401 without valid token
- [ ] MCP endpoints work with valid JWT Bearer token
- [ ] MCP endpoints work with valid X-Agent-Token
- [ ] Existing MCP tests pass with auth headers

### Acceptance Tests

## Issue 2: LLM Providers Are Stubs

**Severity:** High
**File:** `backend/app/llm/gateway.py:22-43`

### Problem

All three LLM providers return fake summaries:
```python
def generate_summary(self, text: str) -> str:
    logger.info("OpenAI provider called (placeholder)")
    return f"Summary generated by OpenAI: {text[:100]}..."
```

The `/reports/{id}/summarize` endpoint silently produces fabricated results.

### Fix

Option A (recommended): Remove the stub implementations. Replace with a single `NullProvider` that raises `NotImplementedError("LLM not configured — set UPCP_LLM_API_KEY")`. The endpoint should return 501 Not Implemented when LLM is not configured.

Option B: Implement real providers using `httpx` to call OpenAI/DeepSeek APIs.

**Recommended:** Option A — stubs are worse than no implementation because they deceive users.

### Implementation

```python
class NullProvider:
    """LLM provider that raises when LLM is not configured."""

    def generate_summary(self, text: str) -> str:
        raise NotImplementedError(
            "LLM not configured. Set UPCP_LLM_API_KEY and UPCP_LLM_PROVIDER."
        )

def get_provider() -> LLMProvider:
    settings = get_settings()
    if not settings.llm_api_key:
        return NullProvider()
    # ... real provider selection
```

### Acceptance Criteria

- [ ] Without LLM config, `/reports/{id}/summarize` returns 501 with clear message
- [ ] With invalid LLM config, returns 502 with error message
- [ ] No fake summaries are ever returned
- [ ] Existing tests pass (update tests that expect fake summaries)

### Acceptance Tests

## Issue 3: CSP Allows unsafe-eval

**Severity:** Medium
**File:** `backend/app/main.py:122`

### Problem

```python
"script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'"
```

`unsafe-eval` allows arbitrary code execution via `eval()`, `new Function()`, etc. This defeats XSS protection.

### Fix

1. Remove `'unsafe-eval'` from script-src
2. Keep `'unsafe-inline'` for now (Vite injects inline scripts in dev) — but add a nonce in production
3. Add `'wasm-unsafe-eval'` if WebAssembly is needed

```python
"script-src 'self' 'unsafe-inline' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'"
```

### Acceptance Criteria

- [ ] CSP header does not contain `'unsafe-eval'`
- [ ] Frontend still loads correctly (no CSP violations)
- [ ] Test verifies CSP header content

### Acceptance Tests

```python

    # When: GET /health
    # Then: Content-Security-Policy header does not contain 'unsafe-eval'
```

## Issue 4: Agent Endpoints Lack Ownership Checks

**Severity:** Low
**File:** `backend/app/identity/agent_endpoints.py`

### Problem

Endpoints like `get_agent`, `agent_claims`, `agent_evidence` require authentication but do not verify that the requesting user owns the agent. Any authenticated user can view any agent's claims, evidence, reviews, and activity.

### Fix

Add ownership check: user must be the agent's creator OR have admin/owner role.

```python
def _check_agent_access(agent_id: str, user_id: str, session: Session) -> Agent:
    agent = session.get(Agent, agent_id)
    if not agent:
        raise NotFound(f"Agent {agent_id} not found")
    # Check ownership or admin role
    if agent.created_by != user_id:
        # Check if user is admin
        user = session.get(User, user_id)
        if not user or not user.is_superuser:
            raise Forbidden("Not authorized to access this agent")
    return agent
```

### Acceptance Criteria

- [ ] Agent owner can access all agent endpoints
- [ ] Admin/superuser can access all agent endpoints
- [ ] Other users get 403 Forbidden
- [ ] Non-existent agent returns 404

### Acceptance Tests

```python

    # Then: response is 200
```

## Issue 5: Test Env Guard Disables All Protections

**Severity:** Medium
**File:** `backend/app/main.py:95,99`

### Problem

```python
if settings.env != "test":
    app.add_middleware(RateLimitMiddleware)
if settings.env != "test":
    app.add_middleware(AuthMiddleware)
```

If `UPCP_ENV` is accidentally set to "test" in production, all protections are disabled.

### Fix

Use separate, explicit flags:
```python
if not settings.disable_rate_limit:
    app.add_middleware(RateLimitMiddleware)
if not settings.disable_auth:
    app.add_middleware(AuthMiddleware)
```

Add to Settings:
```python
disable_rate_limit: bool = Field(default=False, alias="UPCP_DISABLE_RATE_LIMIT")
disable_auth: bool = Field(default=False, alias="UPCP_DISABLE_AUTH")
```

In test conftest, set these flags explicitly rather than relying on `env="test"`.

### Acceptance Criteria

- [ ] `env="test"` no longer disables auth/rate limiting
- [ ] `UPCP_DISABLE_RATE_LIMIT=true` disables rate limiting
- [ ] `UPCP_DISABLE_AUTH=true` disables auth middleware
- [ ] Default: both protections enabled regardless of env
- [ ] All existing tests pass (update conftest to set disable flags)

### Acceptance Tests

```python
def test_auth_enabled_by_default():
    """Auth middleware is active even in test env."""
    # Given: env="test", no disable flags
    # When: GET /api/v1/projects without token
    # Then: response is 401

def test_auth_disabled_explicitly():
    """Auth disabled only with explicit flag."""
    # Given: UPCP_DISABLE_AUTH=true
    # When: GET /api/v1/projects without token
    # Then: response is 200
```
