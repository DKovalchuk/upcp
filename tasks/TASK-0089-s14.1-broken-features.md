### 0.2 — HealthPage Database Status (size: M, 2pts)

**Problem**: Database card **hardcoded** to green "Connected" regardless of actual DB state. Never reads from API. The Backend API card works correctly (reads `health?.status`), but the Database card is completely static.

**Root Cause**: The `HealthResponse` TypeScript type only declares `{ status, service }` — missing the `redis` field the backend already returns, and no `db` field. The Database card never references `health` data at all.

**Chain of breakage**:
```
Backend /health → checks Redis only (no DB check)
→ returns { status, service, redis }
Frontend HealthResponse type → only { status, service } (redis field ignored)
HealthPage Database card → HARDCODED "Connected" (never reads API)
→ If DB is down, user sees "Connected" — misleading
→ Docker healthcheck uses /health, so DB down = container still reports healthy
```

**Acceptance Criteria**:
- [ ] Frontend `HealthResponse` type includes `db: { status: string, latency_ms?: number, error?: string }` and `redis: string`
- [ ] HealthPage Database card reads `health.db.status` from API response
- [ ] Green indicator + "Connected" only when `health.db.status === 'ok'`
- [ ] Red indicator + "Disconnected" when `health.db.status !== 'ok'`
- [ ] Latency displayed when available
- [ ] Optional: Redis card using `health.redis` field
- [ ] Tests: component renders correct DB status based on API response

**Files**:
- `frontend/src/types/api.ts` — update HealthResponse type (add db + redis fields)
- `frontend/src/components/HealthPage.tsx` — dynamic Database card, optional Redis card
- `frontend/src/components/HealthPage.test.tsx` — add tests for DB status variants

### 0.3 — Backend /health Endpoint DB Check (size: M, 2pts)

**Problem**: `/health` checks **only Redis** — no `SELECT 1`, no DB connectivity verification. Docker healthcheck depends on this endpoint, so DB down = container still reports healthy.

**Current response**: `{ status, service, redis }` — no `db` field.

**Existing infrastructure**: `database.py` has `pool_pre_ping=True` on SQLAlchemy engine (validates connections silently) but no exposed health function. Backend `HealthResponse` Pydantic schema at `shared/schemas.py` only declares `status` and `service` — missing `redis` field too.

**Acceptance Criteria**:
- [ ] New `check_db_health()` function: `SELECT 1` via SQLAlchemy session with 5s timeout
- [ ] `/health` calls `check_db_health()` and includes `db` in response
- [ ] Response shape: `{ status, service, db: { status, latency_ms, error? }, redis: { status, error? } }`
- [ ] `status` = `"ok"` if both db+redis ok, `"degraded"` if one fails, `"error"` if both fail
- [ ] Backend Pydantic `HealthResponse` schema updated to match new shape
- [ ] DB check timeout prevents hanging (5s max)
- [ ] Tests: health returns ok when DB available, error when DB unavailable, degraded when one fails

**Files**:
- `backend/app/shared/database.py` — add `check_db_health()` function
- `backend/app/main.py` — update `health()` to include DB check
- `backend/app/shared/schemas.py` — update HealthResponse Pydantic model
- `backend/tests/test_health.py` — update/add tests for DB check

- [ ] `is_stale` = true when last_heartbeat > 7 minutes ago
- [ ] Frontend: TypeScript type `AgentActivityItem` in `types/dashboard.ts`
- [ ] Frontend: `fetchAgentActivity()` in api.ts
- [ ] Frontend: `useAgentActivity()` hook in `use-dashboard.ts`
- [ ] AgentActivitySummary renders real agent data with avatar, name, task, progress bar, heartbeat time
- [ ] Empty state shown only when no agents have active claims
- [ ] Auto-refresh at 30s interval
- [ ] Tests: backend endpoint + frontend component

### 0.5 — ReportsPage: Generation + Export Fix (size: M, 2pts)

**Problem (CRITICAL)**: Report generation is completely broken. Frontend `createReport` POSTs to `/api/v1/projects/${projectId}/reports` but backend only has `POST /api/v1/projects/{project_id}/reports/daily`. **404 on every attempt.** No reports can ever be created.

**Problem (MODERATE)**: `handleExportMarkdown` has 3 additional bugs:
1. Uses raw `fetch()` — no auth token, inconsistent error handling
2. `URL.revokeObjectURL(url)` called synchronously after `a.click()` — race condition causes silent download failures in many browsers
3. No HTTP status check — server errors (404/500) result in downloading a file containing literal text "undefined"

**Acceptance Criteria**:
- [ ] **CRITICAL**: `createReport` in api.ts POSTs to correct URL: `/api/v1/projects/${projectId}/reports/daily`
- [ ] `handleExportMarkdown` uses `apiRequest()` wrapper with auth token
- [ ] `URL.revokeObjectURL` deferred with `setTimeout(() => URL.revokeObjectURL(url), 100)` to avoid race condition
- [ ] HTTP status checked before parsing response (`if (!res.ok) throw`)
- [ ] Error handling matches other API calls (toast on failure)
- [ ] Tests: createReport posts to /daily endpoint, export uses apiRequest

**Files**:
- `frontend/src/lib/api.ts` — fix createReport URL, add exportReportMarkdown
- `frontend/src/components/project/ReportsPage.tsx` — fix export function (apiRequest + revokeObjectURL + status check)

### 0.6 — EntityFormDialog Select + useEffect Bug (size: M, 2pts)

**Problem 1 (PRIMARY)**: Select field uses native HTML `<select>` instead of shadcn `<Select>` from `@/components/ui/select`. Inconsistent with TaskDetailSheet, AuditPage, and DataTablePagination which all use the styled component. Affects 7 select fields across 6 entity types (Project, Component, Module, Feature, Task, Subtask).

**Problem 2 (HIGH)**: `useEffect` dependency on `initialData` — when `ProjectDetail` passes inline object `initialData={{ name, slug, ... }}`, it creates a new reference every render. This causes the useEffect to fire on every parent re-render, **silently resetting form data** and losing unsaved user changes.

**Problem 3 (LOW)**: `subtaskFields` in `entity-fields.ts` is dead code — never imported anywhere.

**Problem 4 (LOW)**: `ProjectList.tsx` duplicates `PROJECT_FIELDS` locally (omitting status select) instead of importing from `entity-fields.ts`.

**Existing Infrastructure**:
- shadcn Select component at `components/ui/select.tsx` (built on @base-ui/react, with portals, animations, keyboard nav)
- `entity-fields.ts` defines all field configs with proper select options
- Test file has 11 passing tests but no test for select value submission

**Acceptance Criteria**:
- [ ] Select fields use shadcn `<Select>`, `<SelectTrigger>`, `<SelectContent>`, `<SelectItem>` from `@/components/ui/select`
- [ ] Visual style matches TaskDetailSheet status select
- [ ] Keyboard navigation works (shadcn Select supports this natively)
- [ ] `useEffect` dependency fixed: compare `initialData` by value (JSON.stringify or useMemo in callers) — prevent form state loss on parent re-render
- [ ] `ProjectList.tsx` imports `projectFields` from `entity-fields.ts` instead of redefining locally
- [ ] Remove dead `subtaskFields` from `entity-fields.ts`
- [ ] `value.trim()` only applied to text/textarea fields, not select values
- [ ] Tests: select renders with shadcn component, form submits selected value, form doesn't reset on re-render

**Files**:

## Risks

1. **Missing GET endpoints for claims/clarifications** (0.1): Workflow endpoints only have POST. Adding GET is straightforward — query models directly in endpoints. **Mitigation**: Simple DB queries, no complex logic needed.

2. **No active-agents endpoint** (0.4): Need new `GET /dashboard/agent-activity`. **Mitigation**: Join existing tables (agent → task_claim → task → heartbeat), straightforward SQL.

3. **DB health check in /health** (0.3): Must handle connection pool timeout gracefully. **Mitigation**: `session.execute(text('SELECT 1'))` with 5s timeout + try/except.

4. **EntityFormDialog useEffect** (0.6): Changing useEffect deps may affect form initialization timing. **Mitigation**: Use JSON.stringify comparison or useMemo in callers. Test re-render stability explicitly.

5. **ReportsPage URL mismatch** (0.5): Critical — report generation has been broken since creation. Single line fix but must verify backend `/daily` endpoint accepts the request body.
