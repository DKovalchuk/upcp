### 1.2 — SSRF Validation (size: M, 1.5pts)

**Problem**: GitHub adapter uses raw `owner`/`repo` in URL construction without validation. No SSRF protection against internal IPs. Audit finding: M-7, SEC-005.

**Current state**: `backend/app/gitread/adapters.py:119-160`

**Acceptance Criteria**:
- [x] `validate_github_owner(owner)` — regex `^[a-zA-Z0-9._-]+$`, max 100 chars
- [x] `validate_github_repo(repo)` — regex `^[a-zA-Z0-9._-]+$`, max 100 chars
- [x] `validate_url_not_internal(url)` — block 127.x, 10.x, 192.168.x, 169.254.x, ::1
- [x] `GitHubAdapter.__init__()` validates owner/repo on construction
- [x] `GitProviderCreate.provider_type` uses `Literal["github", "gitlab", "bitbucket", "local", "other"]`
- [x] Tests: owner/repo validation, internal IP blocking, provider type enum (24 tests)

**Files**:
- `backend/app/shared/url_validation.py` (new)
- `backend/app/gitread/adapters.py`
- `backend/app/gitread/schemas.py`
- `backend/tests/test_ssrf.py` (new)

### 1.3 — Error Sanitization (size: S, 1.5pts)

**Problem**: Git adapter errors expose raw stderr (up to 200 chars). No catch-all handler for unhandled exceptions — FastAPI default leaks stack traces. Audit finding: H-8.

**Current state**: `backend/app/gitread/adapters.py:79`, `backend/app/shared/errors.py:36`

**Acceptance Criteria**:
- [x] Catch-all `@app.exception_handler(Exception)` returns `{"error": "internal_error", "detail": "An unexpected error occurred"}`
- [x] Full exception logged server-side at ERROR level with `exc_info=True`
- [x] Git adapter `_run()` error: generic message to user, raw stderr only in server logs
- [x] Tests: catch-all handler returns sanitized message, git errors don't expose stderr (6 tests)

**Files**:
- `backend/app/shared/errors.py`

## Risks

1. **CORS breaking local dev**: If `UPCP_CORS_ORIGINS` is not set, local dev may break. **Mitigation**: Default to `http://localhost:5173,http://localhost:3000` when env is "local".
2. **SSRF validation too strict**: Legitimate git provider URLs may contain IP addresses. **Mitigation**: Only block private/internal ranges, allow public IPs.
3. **Dependency scan blocking CI**: Existing vulnerabilities may cause immediate CI failure. **Mitigation**: Check current scan output first, fix critical issues if found.
